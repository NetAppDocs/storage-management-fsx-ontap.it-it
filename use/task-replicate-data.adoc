= Replica i dati su FSx per ONTAP in NetApp Console
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Replica i dati per proteggerli dalla perdita se la regione in cui risiedono i tuoi dati subisce un disastro. La replica dei dati è supportata tra file system FSx for ONTAP e sistemi ONTAP on-premises o Cloud Volumes ONTAP.

Quando si replicano i dati e le impostazioni di configurazione di una storage VM, è necessario prima creare e inizializzare la relazione di replica e quindi attendere che i dati vengano sincronizzati almeno una volta prima di completare l'operazione di cutover.



== Informazioni su questo compito

La replica protegge i tuoi dati da disastri regionali e supporta la migrazione delle storage VM.

La replica include la creazione e l'inizializzazione di una relazione di replica. Per configurare la replica, è necessario creare la relazione di replica. Per trasferire i dati tra i sistemi storage di origine e di destinazione, è necessario inizializzare la relazione di replica. Durante la migrazione dei dati e delle impostazioni di configurazione delle VM di storage, è inoltre necessario completare l'operazione di cutover.

I volumi replicati nel file system di destinazione sono volumi di protezione dati (DP) e seguono il formato di denominazione: `{OriginalVolumeName}_copy`.

Se si replica un volume sorgente con file immutabili, il volume di destinazione e il file system rimangono bloccati fino al termine del periodo di conservazione del volume sorgente. La funzionalità dei file immutabili è disponibile quando si link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-volume.html["creare un volume"] per un file system FSx for ONTAP.

[NOTE]
====
È possibile replicare un volume sorgente (read/write) o un volume di protezione dati (DP). La replica a cascata è supportata, ma un terzo hop non lo è. Scopri di più su link:https://docs.netapp.com/us-en/workload-fsx-ontap/cascade-replication.html["replicazione a cascata"^].

====


=== Casi d'uso della migrazione

Per la migrazione, è possibile scegliere di replicare i dati e le impostazioni di configurazione di una singola storage VM. Se si migrano dati e impostazioni di configurazione insieme, assicurarsi che l'ultima replica del volume sia stata completata nelle ultime 24 ore. È necessario selezionare tutti i volumi nella stessa storage VM per utilizzare questa funzionalità. La policy di tiering per tutti i volumi viene impostata di default sulla policy di tiering del volume di origine, che è consigliata per i casi d'uso di migrazione.

Workload Factory supporta la replica della migrazione tra i seguenti sistemi storage.

* Sistemi ONTAP on-premises e file system FSx for ONTAP
* Cloud Volumes ONTAP e FSx per ONTAP file system
* FSx per ONTAP e FSx per ONTAP file system
+
** Prima alla prima generazione
** Seconda alla seconda generazione




Per migrare i dati e le impostazioni di configurazione delle storage VM, è necessario completare tre operazioni.

. <<Passaggio 1: Creare la relazione di replica,Creare la relazione di replica>>, seleziona *Migration* come caso d'uso e seleziona *Replicate storage VM configuration*.
. <<Passaggio 2: Inizializzare la relazione di replica,Inizializza la relazione di replica>> per trasferire i dati dal sistema di origine al sistema storage di destinazione.
. <<Fase 3: Cutover della replica per i casi d'uso di migrazione,Cut over replication per casi d'uso di migrazione>> per migrare in modo permanente dati e impostazioni di configurazione dal file system di origine al file system FSx for ONTAP di destinazione.




== Passaggio 1: Creare la relazione di replica

Replica i dati tra due file system FSx for ONTAP, tra un sistema ONTAP on-premises e un file system FSx for ONTAP, oppure tra Cloud Volumes ONTAP e un file system FSx for ONTAP.

.Prima di iniziare
Rivedi questi requisiti prima di iniziare.

* Per replicare i dati tra FSx for ONTAP e ONTAP on-premises o Cloud Volumes ONTAP, è necessario associare un collegamento a un file system. link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-link.html["Scopri come associare un collegamento esistente o creare e associare un nuovo collegamento"]. Dopo aver associato il collegamento, tornare a questa operazione.
* Per la replica da un sistema ONTAP on-premises a un file system FSx for ONTAP, assicurati di aver individuato il sistema ONTAP on-premises.
* La replica non è supportata per i volumi in uno stato diverso da disponibile, creato o configurato in modo errato e quando la versione di ONTAP non è compatibile.
* Per i casi d'uso di migrazione, assicurati che l'ultima replica per il volume sia stata completata nelle ultime 24 ore prima di creare una relazione di replica con dati e impostazioni di configurazione della storage VM.


.Passi
. Dalla pagina Systems della NetApp Console, trascina il file system FSx for ONTAP di origine, il sistema ONTAP on-premises o il sistema Cloud Volumes ONTAP sopra il file system FSx for ONTAP di destinazione e seleziona *Replication*.
. Nella pagina Crea replica, seleziona i volumi di origine da replicare, quindi *Avanti*.
. In Destinazione replica, fornire quanto segue:
+
.. *Nome destinazione*: hai applicato il nome destinazione quando hai trascinato e rilasciato il sistema storage di origine sul sistema di destinazione nella pagina Console Systems.
.. *Caso d'uso*: selezionare uno dei seguenti casi d'uso per la replica.  A seconda del caso d'uso selezionato, Workload Factory compila il modulo con i valori consigliati in conformità con le best practice.  È possibile accettare i valori consigliati o apportare modifiche durante la compilazione del modulo.
+
*** Intelligenza artificiale (AI) e machine learning (ML): replica i tuoi dati ONTAP on-premises su Amazon FSx for NetApp ONTAP e crea punti di accesso S3 per supportare l’addestramento di AI e ML nel cloud
*** Migrazione: trasferisce i dati al file system FSx for ONTAP di destinazione
+
*Replica configurazione VM di storage*: facoltativamente, seleziona per replicare i dati e le impostazioni di configurazione della VM di storage per una singola VM di storage. Quando si migrano dati e impostazioni di configurazione simultaneamente, assicurati che l'ultima replica per il volume sia stata completata nelle ultime 24 ore. Tutti i volumi nella stessa VM di storage devono essere selezionati per utilizzare questa funzionalità. La policy di tiering per tutti i volumi predefinita è quella del volume di origine, che è consigliata per i casi d'uso di migrazione.

*** Ripristino di emergenza a caldo: garantisce elevata disponibilità e rapido ripristino di emergenza per carichi di lavoro critici
*** Ripristino di emergenza a freddo o in archivio:
+
**** Ripristino di emergenza a freddo: utilizza obiettivi di tempo di ripristino (RTO) e oggetti di punto di ripristino (RPO) più lunghi per ridurre i costi
**** Archivio: replica i dati per l'archiviazione a lungo termine e la conformità


*** Altro
+
Inoltre, la selezione del caso d'uso determina la politica di replicazione, o politica SnapMirror (ONTAP).  I termini utilizzati per descrivere le politiche di replicazione provengono dalink:https://docs.netapp.com/us-en/ontap/data-protection/default-protection-policies-concept.html["Documentazione ONTAP 9"^] .

+
**** Per la migrazione e altro, la politica di replicazione si chiama _MirrorAllSnapshots_.  _MirrorAllSnapshots_ è una policy asincrona per il mirroring di tutti gli snapshot e dell'ultimo file system attivo.
**** Per il disaster recovery a caldo, a freddo o tramite archivio, la policy di replica è denominata _MirrorAndVault_.  _MirrorAndVault_ è una policy asincrona e di vault per il mirroring del file system attivo più recente e degli snapshot giornalieri e settimanali.
+
Per tutti i casi d'uso, se si abilitano gli snapshot per la conservazione a lungo termine, il criterio di replica predefinito è _MirrorAndVault_.





.. *FSx for ONTAP file system*: seleziona credenziali, regione e nome del FSx for ONTAP file system per il file system di destinazione FSx for ONTAP.
.. *Nome VM di archiviazione*: seleziona la VM di archiviazione dal menu a discesa.  La VM di archiviazione selezionata è la destinazione per tutti i volumi selezionati in questa relazione di replica.
.. *Nome volume*: il nome del volume di destinazione viene generato automaticamente con il seguente formato `{OriginalVolumeName}_copy` .  È possibile utilizzare il nome del volume generato automaticamente oppure immettere un altro nome del volume.
.. *Criterio di suddivisione in livelli*: selezionare il criterio di suddivisione in livelli per i dati archiviati nel volume di destinazione.  Per impostazione predefinita, la politica di suddivisione in livelli è quella consigliata per il caso d'uso selezionato.
+
_Bilanciato (Automatico)_ è il criterio di suddivisione in livelli predefinito quando si crea un volume utilizzando la console Workload Factory.  Per ulteriori informazioni sulle politiche di suddivisione in livelli del volume, fare riferimento alink:https://docs.aws.amazon.com/fsx/latest/ONTAPGuide/volume-storage-capacity.html#data-tiering-policy["Capacità di archiviazione del volume"^] nella documentazione di AWS FSx per NetApp ONTAP .  Si noti che Workload Factory utilizza nomi basati sui casi d'uso nella console Workload Factory per i criteri di suddivisione in livelli e include i nomi dei criteri di suddivisione in livelli FSx for ONTAP tra parentesi.

+
Se hai selezionato il caso d'uso di migrazione, Workload Factory sceglie automaticamente di copiare la policy di suddivisione in livelli del volume di origine nel volume di destinazione.  È possibile deselezionare la copia del criterio di suddivisione in livelli e selezionare un criterio di suddivisione in livelli che si applichi al volume selezionato per la replica.

.. *Velocità di trasferimento massima*: seleziona *Limitata* e inserisci il limite massimo di trasferimento in MB/s.  In alternativa, seleziona *Illimitato*.
+
Senza limiti, le prestazioni della rete e delle applicazioni potrebbero diminuire.  In alternativa, consigliamo una velocità di trasferimento illimitata per FSx per i file system ONTAP per carichi di lavoro critici, ad esempio quelli utilizzati principalmente per il ripristino di emergenza.



. Nelle impostazioni di replica, specificare quanto segue:
+
.. *Intervallo di replica*: seleziona la frequenza con cui gli snapshot vengono trasferiti dal volume di origine al volume di destinazione.
.. *Conservazione a lungo termine*: facoltativamente, abilitare gli snapshot per la conservazione a lungo termine.  La conservazione a lungo termine consente ai servizi aziendali di continuare a funzionare anche in caso di guasto completo del sito, supportando il failover delle applicazioni in modo trasparente utilizzando una copia secondaria.
+
Le repliche senza conservazione a lungo termine utilizzano il criterio _MirrorAllSnapshots_.  L'abilitazione della conservazione a lungo termine assegna il criterio _MirrorAndVault_ alla replica.

+
Se si abilita la conservazione a lungo termine, selezionare un criterio esistente o crearne uno nuovo per definire gli snapshot da replicare e il numero da conservare.

+

NOTE: Per una conservazione a lungo termine è necessario che le etichette di origine e di destinazione corrispondano.  Se lo desideri, Workload Factory può creare per te le etichette mancanti.

+
*** *Scegli una polizza esistente*: seleziona una polizza esistente dal menu a discesa.
*** *Crea una nuova policy*: inserisci un *nome policy*.


.. *Snapshot immutabili*: Facoltativo.  Selezionare *Abilita snapshot immutabili* per impedire che gli snapshot acquisiti in questo criterio vengano eliminati durante il periodo di conservazione.
+
*** Imposta il *Periodo di conservazione* in numero di ore, giorni, mesi o anni.
*** *Criteri di snapshot*: nella tabella, seleziona la frequenza dei criteri di snapshot e il numero di copie da conservare.  È possibile selezionare più di un criterio snapshot.


.. *Punto di accesso S3*: facoltativamente, collega un punto di accesso S3 per accedere ai dati del file system FSx for ONTAP residenti su volumi NFS o SMB/CIFS tramite le API AWS S3. È supportato solo il tipo di accesso ai file. Fornire i seguenti dettagli:
+
*** *Nome punto di accesso S3*: Inserisci il nome del punto di accesso S3.
*** *Utente*: Seleziona un utente esistente con accesso al volume o crea un nuovo utente.
*** *Tipo di utente*: seleziona *UNIX* o *Windows* come tipo di utente.
*** *Configurazione di rete*: seleziona *Internet* o *Virtual private cloud (VPC)*. Il tipo di rete scelto determina se il punto di accesso è accessibile da Internet o limitato a una VPC specifica.
*** *Abilita tabella inventario*: quando si abilita la tabella inventario sul volume, il sistema genera metadati per tutti gli oggetti accessibili al punto di accesso S3 e comporta costi di richiesta AWS S3. Consultare link:https://aws.amazon.com/s3/pricing/["Documentazione sui prezzi di Amazon S3"^] per ulteriori informazioni.


.. *Tag del punto di accesso S3*: Facoltativamente, puoi aggiungere fino a 50 tag.




. Seleziona *Crea*.


.Risultato
La relazione di replica appare nella scheda *Relazioni di replica* nel file system FSx for ONTAP di destinazione.

Se hai creato una relazione di replica per scopi di migrazione, devi eseguire il cutover di tutti i volumi e della relativa storage VM associata per completare la migrazione dei dati e delle impostazioni di configurazione della storage VM nel file system FSx for ONTAP di destinazione.



== Passaggio 2: Inizializzare la relazione di replica

Inizializza una relazione di replica tra i volumi di origine e di destinazione per trasferire lo snapshot e tutti i blocchi di dati in NetApp Workload Factory.

L'inizializzazione esegue un trasferimento baseline: crea un'istantanea del volume di origine, quindi trasferisce l'istantanea e tutti i blocchi di dati a cui fa riferimento al volume di destinazione.

.Prima di iniziare
Valuta attentamente il momento migliore per completare questa operazione. L'inizializzazione può richiedere molto tempo. Potresti preferire eseguire il trasferimento baseline nelle ore di minor traffico.

.Passi
. Nella NetApp Console, seleziona il menu image:workloads-menu-icon.png["L'icona del menu hamburger viene utilizzata per navigare tra carichi di lavoro come storage, eda, ai, databases, vmware e amministrazione."] e poi seleziona *Archiviazione*.


. Dal menu Storage, selezionare *FSx for ONTAP*.
. Da *FSx per ONTAP*, selezionare il menu delle azioni del file system da aggiornare e quindi selezionare *Gestisci*.
. Dalla panoramica del file system, selezionare la scheda *Relazioni di replica*.
. Nella scheda Relazioni di replica, selezionare il menu Azioni della relazione di replica da inizializzare.
. Seleziona *Inizializza*.


. Nella finestra di dialogo Inizializza relazione, selezionare *Inizializza*.
+
Quando lo stato della replica mostra *Idle*, il trasferimento dei dati è completato.





== Fase 3: Cutover della replica per i casi d'uso di migrazione

Dopo aver creato la relazione di replica per un caso d'uso di migrazione, è necessario eseguire il cutover della replica per completare la migrazione dei dati e delle impostazioni di configurazione della storage VM al file system FSx for ONTAP di destinazione. Il cutover della replica migra in modo permanente i dati e le impostazioni di configurazione della storage VM dal file system di origine al file system FSx for ONTAP di destinazione. Durante il cutover, i dati vengono replicati per l'ultima volta. La storage VM di origine va offline quando inizia il cutover.



=== Pianifica l'operazione di cutover

Considerare quanto segue quando si pianifica l'operazione di cutover per i casi d'uso di migrazione.

* *Supporto della versione di replica*: i sistemi storage di origine e di destinazione devono avere la stessa versione principale di ONTAP. Ad esempio, se il sistema di origine esegue la versione di ONTAP 9.18.1, anche il sistema di destinazione deve eseguire una versione di 9.18.1.
* *Impostazioni di configurazione della VM di storage*: l'operazione di cutover non migra tutte le impostazioni di configurazione della VM di storage alla VM di storage di destinazione. Ad esempio, le impostazioni iSCSI, MTU del dominio broadcast e DNS non vengono migrate. Aggiornare manualmente queste impostazioni sulla VM di storage di destinazione dopo il cutover. Per ulteriori dettagli, fare riferimento alla sezione <<Aggiornare le impostazioni di configurazione dopo cutover,Aggiornare le impostazioni di configurazione dopo cutover>>.
* *Cloni*: I cloni vengono migrati come volumi individuali e, pertanto, occuperanno più spazio sul file system FSx for ONTAP di destinazione. Si consiglia di eliminare i cloni prima del cutover per evitare un aumento della capacità sul sistema di destinazione.
* *Volumi cache*: Per ONTAP FlexCache 9.17.x o versioni precedenti. Le VM di storage di origine che contengono volumi cache non sono supportate per cutover. Rimuovere la relazione ONTAP FlexCache prima del cutover per evitare errori di migrazione.
* *Punti di accesso AWS S3*: la replica di cutover per i casi d'uso di migrazione non è supportata per i volumi con punti di accesso S3. Eliminare i punti di accesso S3 dal volume di origine per evitare errori di migrazione.
* *ONTAP S3 configurations*: La replica di cutover per i casi d'uso di migrazione non è supportata per i vserver con configurazioni ONTAP S3. Rimuovere le configurazioni ONTAP S3, inclusi object-store-server, bucket, utenti, gruppi o policy sul vserver, per evitare errori di migrazione.
* *Numeri di serie LUN e iSCSI target IQN*: I numeri di serie LUN e l'iSCSI target IQN cambiano durante cutover.


.Prima di iniziare
Rivedi questi requisiti prima di iniziare.

* Interrompere l'accesso dei client alla storage VM prima di eseguire il cutover della replica.
* Assicurarsi che tutti i volumi di origine non stiano servendo alcun dato prima di eseguire il cutover della replica.
* Assicurarsi che i dati siano sincronizzati tra i volumi di origine e di destinazione prima di eseguire il cutover della replica.
* Il file system FSx for ONTAP utilizzato per la relazione di replica deve avere un collegamento associato. link:https://docs.netapp.com/us-en/workload-fsx-ontap/create-link.html["Scopri come associare un collegamento esistente o creare e associare un nuovo collegamento"]. Dopo aver associato il collegamento, tornare a questa operazione.
+
** Nel gruppo di sicurezza associato al file system FSx for ONTAP, per la connettività del collegamento, devono essere aperte le seguenti porte: porta 443 (HTTPS) e porta 22 (SSH).




.Passi
. Nella NetApp Console, seleziona il menu image:workloads-menu-icon.png["L'icona del menu hamburger viene utilizzata per navigare tra carichi di lavoro come storage, eda, ai, databases, vmware e amministrazione."] e poi seleziona *Archiviazione*.


. Dal menu Storage, selezionare *FSx for ONTAP*.
. Da *FSx for ONTAP*, seleziona il file system che contiene il volume o i volumi da replicare.
. Seleziona la scheda *Replication relationships*.
. Nella tabella Relazioni di replicazione, seleziona la relazione di replicazione su cui eseguire il cutover, quindi seleziona *Cut over replication*.
. Rivedere le informazioni nella finestra di dialogo Cut over replication e quindi digitare _cut over_ per confermare.


. Seleziona *cutover*.




=== Aggiornare le impostazioni di configurazione dopo cutover

Dopo aver eseguito il cutover della replica per i casi d'uso di migrazione, aggiornare le seguenti impostazioni di configurazione della storage VM sulla storage VM di destinazione.

* Per iSCSI:
+
** Ricrea l'igroup
** Aggiorna la mappatura LUN
** Accedere a ciascun client SAN e aggiornare le impostazioni iSCSI/MPIO per il nuovo target e rimuovere i vecchi indirizzi IP del target vserver


* Verificare che le impostazioni MTU del dominio broadcast siano conformi alle aspettative
* Verificare che le impostazioni DNS siano conformi alle aspettative
* Ricrea le relazioni della cache (relazioni ONTAP FlexCache) se erano presenti volumi di cache nella VM di archiviazione di origine.
